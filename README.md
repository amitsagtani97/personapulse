# PersonaPulse

A visual synthetic-shopper studio for comparing Target and Walmart clothing. Ten small shopper characters move through a store floor while their journeys run. Afterwards, the report, individual replays, focus group, and What-if lab use the same results.

## Run locally

Requires Node.js 22 or newer. No dependency install is required.

```bash
cp .env.example .env
npm start
```

Open <http://localhost:4173>. With empty keys, the app runs a clearly labeled seeded demo. `npm run check` checks JavaScript syntax; `npm run build` emits the Cloudflare-compatible Worker under `dist/`.

## Make it live

Set `ZOOWORK_API_KEY` in `.env` locally, or as a server secret in the hosted Site. When you press **Start live run**, PersonaPulse creates ten separate ZooWork Managed Agents, each with its own shopper mission and session, waits for their reports, then stops and deletes the agents. The report records each completed shopper as **LIVE AGENT**; failed shoppers retain a visible demo fallback label. ZooWork calls and credentials run entirely on the server.

Set `TAVILY_API_KEY` to retrieve current Target and Walmart clothing search excerpts before the shopper runs. The agents analyze those excerpts. They do **not** browse a retailer checkout or verify inventory or final prices, and the UI says so. Without Tavily, ZooWork can still run, but the agents should report weak evidence. The comparison is a research hypothesis, not measured conversion.

For an optional Band room mirror, create a room and an existing participant the configured agent may mention. Set `BAND_API_KEY`, `BAND_CHAT_ID`, `BAND_MENTION_ID`, and `BAND_MENTION_HANDLE`. Live focus group follow-ups are generated by a ZooWork moderator from the completed shopper reports; when Band is configured, PersonaPulse sends the exchange to the Band room. This is a room mirror, **not** ten independently hosted Band agents. Band requires an explicit mention to route a message.

Do not place keys in `web/`, expose them in frontend code, paste them into a demo URL, or commit `.env`.

## Demo flow

1. Start a run on the store floor and watch each character visit Target, Walmart, and the analysis desk.
2. Open **Report** to compare preferences and directional confidence scores.
3. Open **Shopper replays** to read each shopper's decision trace and links to source excerpts when available.
4. Ask a follow-up in **Focus group**. With ZooWork connected, the answer is generated from the panel's reports.
5. Run a **What-if test**. With ZooWork connected, the agent names affected shoppers and proposes a real A/B test without inventing an uplift number.

## Structure

- `web/`: store scene, dashboard, shopper data, and styles
- `worker/index.js`: same-origin API and sponsor adapters; no browser-visible secrets
- `server.mjs`: local Node host for the same Worker app
- `scripts/build.mjs`: embeds web assets in the deployable Worker
- `.openai/hosting.json`: existing private Site identity
